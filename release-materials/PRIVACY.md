# TokenMonitor data handling

TokenMonitor reads local Codex rollout files and task metadata to display token usage, estimated tool/skill context, and account allowance telemetry already recorded by Codex. It writes local monitor state, preferences, installation metadata, and bounded error-class diagnostics. Hook payload handling stores task identifiers and local transcript/workspace paths, not prompt or tool-result bodies.

Local-only monitoring transmits nothing. Optional SSH remote monitoring sends parsed token metrics, bounded call history, compaction and attribution aggregates, task IDs, derived task titles, and workspace basenames to the configured viewing Mac. Raw transcripts, transcript paths, prompts and tool arguments/results stay on the source Mac. Derived titles may reveal task context. The monitor does not call a model, use an API key, or run a remote MCP server. Private keys stay at their original local paths; passphrases are handled by the SSH agent/macOS Keychain, never by TokenMonitor. Remote configuration is stored in ~/.codex/usage-monitor/remotes.json. Removing a connection does not revoke its public key on the source Mac. Codex plugin delivery is handled by Codex; the setup script copies the bundled app without downloading anything. Skill invocation is processed by Codex as an ordinary request, separate from the monitor runtime.

State is stored under ~/.codex/usage-monitor, preferences under the app's local.codex.usage-monitor domain. Setup modifies only its app, per-user launch helper, and exact owned registrations in ~/.codex/hooks.json, preserving backups and unrelated handlers. Ordinary uninstall retains monitor state; explicitly requested purge removes it. Neither mode deletes Codex conversation transcripts.

TokenMonitor is an independent utility, not an OpenAI product. Context attribution, cache temperature, and compaction economics are estimates, not billing guarantees. Public-directory review and publisher identity verification are separate from local package validation.
