# Contributing

Use `dev` for ongoing work. Keep `main` stable and promote through a validated pull request. Preserve history and make focused local commits after verified milestones. Do not push private validation changes until the maintainer confirms the Mac deployment.


Start with the [documentation index](docs/index.md), [development guide](docs/guides/development.md), [testing guide](docs/guides/testing.md), and [release procedure](docs/guides/releasing.md).

Update the authoritative topic document with behavior changes in the same commit. Add new topics to the index. Release preparation updates notes, validation, changelog and version links. Preserve historical evidence; do not rewrite previous validation as current results.
